## CAP clock finding

The reviewer changed one CAP ledger retrieval clock in an isolated tree built
from retained fixtures. The HTTP 200 entry moved from `14:00:00Z` to
`14:00:01Z` on 5 November 2026. The original raw bytes and prepared snapshot
were intact. Save and restore accepted the tree, but actual preparation at
the recorded `14:00:00Z` cutoff raised `SourceUnavailable`. Matching only the
raw path and source URL missed the clock mismatch.

D75 records the fix before implementation. CAP preparation depends on both
its original retrieval and its validation check. The collector can retain
the earlier content clock while using a new dated path for identical bytes,
so control verification binds the content clock to the URL and digest.
