### Important — P2: preserve the actual CAP warning headline in prepared output

**Primary location:** `src/atlas/ingest/s09_prepare.py:84` (`warning_text: row["event"]`).

**Supporting locations:** `src/atlas/ingest/s09.py:193` selects event/severity/times/instruction without headline; `tests/test_lens.py:43` requires browser warning text to equal the raw English CAP headline; `web/src/components/PlaceLens.tsx:13` renders that field in the report. The preparer regression instead checks the already reduced event value (`tests/sources/test_s09_prepare.py:96`).

The real retained Karnataka fixture contains a headline naming Bengaluru Rural, Bengaluru Urban, Chikkaballapura, Kolar and Mandya, with the provider's likelihood and “next 3 hours” wording. Preparation reduces this to `Thunderstorm with Lightning`; the separate area text is only `5 districts of Karnataka`, and the instruction is only `Please follow SDMA guidelines.` The complete headline is absent from the entire generated envelope. Consequently the area-only warning and eventual printed/shared report lose the district names and warning qualifications that the browser's hand-authored real-source fixture preserves. A source link is retained, but it does not fulfill the warning-text contract or make that information available within the dated report.

**Verification:** one isolated reproduction used the repository Python 3.12 environment with `-B`, copied the original committed fixture into a new raw store, called the actual `prepare()` at its existing test cutoff, and inspected the generated envelope. ### Important — P2: refuse disabled S09 before standalone preparation

**Primary location:** `src/atlas/ingest/s09_prepare.py:179` loads the source configuration, but the only adapter call enforcing `enabled` is inside the display-row loop at line 188. Header-only Cancel/Update messages skip that call.

The standalone `prepare` command therefore bypasses source disablement when retained inputs contain valid controls and no displayable warning. It writes a new prepared pointer with partial source health and a successful validation clock. This violates the project's disabled-source contract and differs from both the collector and the combined refresh command, which refuse disabled sources. The issue is conditional: ordinary warning rows may trigger the adapter's guard, so testing only warning-filled input does not expose it.

**Verification:** a second isolated Python 3.12 `-B` reproduction retained only the existing fixture-derived header-only Cancel control. Both configuration readers (`s09_prepare.load_state` and `s09_collect.load_state`) returned the same S09 configuration with `enabled=False`, without changing any repository configuration or original fixture. The actual standalone preparer returned:

```text
scratch: D:\monsoon-atlas\.cache\p1-review-disabled-cap-_swk6c5v
configured_enabled: False
status: prepared
records: 0
source_health.status: partial
source_health.last_success_at: 2026-11-05T13:59:00Z
```

**Fix:** check S09 enablement at the start of standalone preparation, before retained-input reads and output creation; raise `SourceUnavailable` unconditionally for a disabled source. Cover header-only controls and out-of-state/no-display evidence in the disabled-source regression, and assert that an existing output pointer is unchanged. The combined refresh refusal should remain intact.
