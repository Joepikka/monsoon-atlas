# S04 Open-Meteo CAMS air-quality estimates: discovery (T049)

**Outcome: available.** Hourly CAMS global model forecasts of PM2.5, PM10 and NO2 (0.4 degree),
free without a key, under CC BY 4.0. Checked on 9 Nov 2026 (12 evidence files, fetched 04:50 to
04:54 UTC). Structured record: [`configs/sources/s04.yaml`](../../configs/sources/s04.yaml).
Evidence manifest: [`tests/fixtures/s04/manifest.json`](../../tests/fixtures/s04/manifest.json).

## Access, licence and limits

- `GET https://air-quality-api.open-meteo.com/v1/air-quality` needs no key, account or card.
- Same licence and limits as S01 to S03: CC BY 4.0, free API for non-commercial use, fewer than
  10,000 calls a day (e02, e03). The API host robots.txt disallows crawlers (e01); D31 applies.
- The licence page credits Copernicus for air quality forecasts, but its Copernicus licence link
  returns 404, so the upstream terms were not read. Credit Open-Meteo and CAMS (Copernicus).

## What to request

`hourly=pm2_5,pm10,nitrogen_dioxide`, `timezone=GMT` and `domains=cams_global`. Karnataka is
outside the European domain: `domains=cams_europe` gets HTTP 400 "No data is available for this
location". The default `auto` returns the same values as `cams_global` at Bengaluru (e08, e10),
but T050 names the domain so that the product and its run time are known.

## Issue and valid times (source-specific check: pass)

The response has no run time (e08). The Model Updates page script builds
`https://air-quality-api.open-meteo.com/data/cams_global/static/meta.json` (e05, e06). On
9 Nov 2026 it gave (e07, e09, the same before and after the call):

| Field | Value |
|---|---|
| `last_run_initialisation_time` | 2026-11-08 12:00 UTC (the issue time) |
| `last_run_availability_time` | 2026-11-08 21:48:32 UTC |
| `data_end_time` | 2026-11-13 13:00 UTC, exclusive: the last value is at 12:00 and later hours are null |
| Time step and update interval | 1 hour; every 12 hours |

The docs table says CAMS global is 3-hourly, but the metadata and the response are hourly; T050
stores what the API returns and does not claim a native step.

Rules for T050 and every model that uses S04:

1. CAMS values are **model estimates**, never CPCB observations: rows get provenance `model`
   and product `cams_global`, and the map labels them as CAMS estimates.
2. Pollutants are >= 0; a negative value is rejected, a null stays null.
3. Keep both times: `valid_at` from `hourly.time` (UTC) and `issued_at` from the metadata,
   read before and after the call; keep the forecast only if the run did not change.
4. Past hours have no run time: they are a hindcast archive with `issued_at` null, not
   forecasts available at issue time. Store every run, because the API keeps no vintages (D07).
