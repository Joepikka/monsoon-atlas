# S07 NASA POWER daily point: discovery (T055)

**Outcome: available.** Daily point values of corrected precipitation, 2 m temperature and
all-sky shortwave from NASA POWER, free without a key, with no use restrictions (CC BY 4.0 on
the AWS registry; cite POWER). Model and satellite products, not station observations. Checked
on 9 Nov 2026 (29 evidence files, fetched 06:44 to 06:49 UTC). Structured record:
[`configs/sources/s07.yaml`](../../configs/sources/s07.yaml). Evidence manifest:
[`tests/fixtures/s07/manifest.json`](../../tests/fixtures/s07/manifest.json).

## Access, licence and limits

- Route: `GET https://power.larc.nasa.gov/api/temporal/daily/point?parameters=...&community=AG&longitude=...&latitude=...&start=YYYYMMDD&end=YYYYMMDD&format=JSON&time-standard=UTC`
  (e03). No key, account or card.
- robots.txt disallows `/api/` and blocks AI training crawlers (e01), but the docs invite
  scripted API use (e04). D106 applies D31: documented calls only, 3 seconds apart, once per
  location and range, never crawling.
- Licence: "There are no restrictions on the use, access, and/or download of data", CC BY 4.0,
  cite the POWER project (e29). The referencing guide also asks for the service version and
  access date, a notice of publications and notification of redistribution to other researchers
  (e11). Record the API version (`v2.10.3` in e16) with every fetch.
- No numeric quota; HTTP 429 exists, at most 20 parameters per point request, and repeated
  requests for the same location may be blocked (e02, e03).

## Fill values, units and products (source-specific check: pass)

| Check | Finding | Evidence |
|---|---|---|
| Fill value | header `fill_value` -999.0; 8 Nov 2026 is -999 for all; shortwave -999 before 1984 and after 31 Aug 2026 | e16, e19 |
| Units | PRECTOTCORR mm/day, T2M C, ALLSKY_SFC_SW_DWN MJ/m^2/day with `community=AG` | e16 |
| Units differ by community | `community=RE` gives shortwave in kW-hr/m^2/day (12.11 becomes 3.3629) | e17 |
| Time standard | default LST gives other rain and temperature values than UTC for the same dates | e16, e18 |
| Products per request | Jan 1990: MERRA2, SRB; Jul 2024: MERRA2, SYN1DEG; 1981-2026: MERRA2, GEOSIT, SRB, SYN1DEG | e16, e19, e20 |
| Meteorology switch | MERRA2 alone for Sep 2026; both for 1-8 Oct; GEOSIT alone from 9 Oct 2026 | e23-e27 |

The header names the products behind a whole request, not each day, and the data sources page
is missing (404). Rules for T056 and every model that uses S07:

1. Decode -999 (read from `header.fill_value`) as null with a reason, never as a value.
2. Read units from `parameters` in each response and refuse unexpected units; request
   `community=AG` for MJ/m^2/day.
3. Record the header `sources` and API version with every row. A request whose header lists
   both MERRA2 and GEOSIT must be split until each part names one meteorology product; never
   merge products silently.
4. Name the time standard explicitly and record it.
5. Values are model and satellite estimates (provenance `model`), not observations.

## Adapter (T056)

`src/atlas/ingest/s07.py` requests PRECTOTCORR, T2M and ALLSKY_SFC_SW_DWN for one point with
`community=AG` and `time-standard=UTC`, from 1981-01-01 on. `fetch` waits 3 seconds between
calls (D106) and splits a date range in half until each response names at most one
meteorology product (MERRA2 or GEOSIT) and one solar product (SRB or SYN1DEG); a single day that
still names two fails. `parse` refuses mixed or unknown products, other units, a non-UTC time
standard and a missing fill value. It writes one row per point and UTC day: the envelope plus
`cell_id`, `date_local`, `met_product`, `solar_product`, `api_version`, `rain_mm`, `tmean_c`,
`solar_mj_m2` and `solar_missing_reason` (`schemas/s07.json`). -999 becomes null: missing rain
or temperature nulls both with `missing_reason` (`not_yet_available` after the newest complete
day, else `out_of_coverage`); solar has its own `solar_missing_reason`, because it lags months
behind and must not erase good rain and temperature (the S32 pattern). Negative values are
`quality_rejected`. `record_id` includes the products, so a day later served by another product
is kept as a new version. Three T055 responses (e16, e20, e21) are committed as test fixtures;
S07 is enabled in `configs/states/ka.yaml`.
