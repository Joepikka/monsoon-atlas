## Access, licence and limits

- `GET https://flood-api.open-meteo.com/v1/flood` needs no key, account or card.
- Same licence and limits as S01/S02: CC BY 4.0, free API for non-commercial use, fewer than
  10,000 calls a day (e02, e03). The API host robots.txt disallows crawlers (e01); D31 applies.
- The licence page credits GloFAS, but its GloFAS licence link returns 404, so the upstream
  terms were not read. Credit Open-Meteo and GloFAS (Copernicus).

## What to request

`daily=river_discharge` with `timezone=Asia/Kolkata`. The default model is GloFAS v4
Seamless, which joins the consolidated history and the forecast (e04); T048 must name one
model and record it. Ensemble members exist only for forecasts.

Rules for T048 and every model that uses S03:

1. GloFAS discharge is **model output**, not a gauge: rows get provenance `model`.
2. Missing cells stay null, never 0; every sampled value is >= 0.
3. At 5 km the nearest river can be the wrong one (e04): choose each river cell per site and
   check it, and record the first non-null date per cell instead of assuming 1984.
4. Past values are a hindcast unless the forecast was stored at issue time (plan rule "S03
   discharge vintage at issue").

## Adapter (T048)

`src/atlas/ingest/s03.py` requests `models=seamless_v4` (named explicitly; the same values as
the default, e07 and e11; an unknown name gets HTTP 400) with IST days and writes the envelope
plus `river_cell_id`, `valid_date`, `discharge_m3s`, `member` and `product`
(`schemas/s03.json`). `valid_at` is the end of the IST day; `available_at` is the fetch time;
provenance is `model`. A null stays null: `not_yet_available` after the cell's newest value,
otherwise `out_of_coverage`; a negative value is `quality_rejected`. Two T047 responses (e11,
e08) are committed as CC BY 4.0 test fixtures. S03 is enabled in `configs/states/ka.yaml`.
